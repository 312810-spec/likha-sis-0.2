## Ownership, identity and decisions

ClassRecordJourneyScreen mounts the active workspace or Studio. Both call AssessmentApplicationService.deleteItem(canonical ID); the service validates/trims ID. The unchanged Rust command locks the database and derives active school scope; repository delete checks in-school identity and existing scores before its DELETE. Score recording shares the connection mutex, so native ordering determines the accepted operation. This is source inspection, not new native/device execution. Existing rename/full-update and score restrictions remain.

A single busy ID cannot represent two in-flight requests. Global serialization was rejected because items are independently actionable. Per-ID ref membership guards duplicate dispatch synchronously; per-ID state renders each pending request. Each completion removes only its own membership. Clearing a prepared confirmation and workspace selection uses current-state functional comparison with canonical ID. Text labels do not substitute for identity.

An exception is an unconfirmed result, not proof of failed deletion. The actionable list is invalidated and the existing read-only Reload items path is required. A reload-required latch prevents other successful write callbacks from implicitly recovering the list; read generations reject responses started before invalidation or a newer read. Explicit reload starts a new generation and reconciles actual fixture/current records without replaying any write.
