## Ownership and consequences

ClassRecordJourneyScreen mounts the active Scores workspace (keyed by teacher/assignment/class record) or Studio. Both edit handlers call AssessmentApplicationService.renameItem for already-scored items and updateItem for unscored items; canonical ID, category and maximum are captured by that invocation. The service trims/validates; the existing native boundary rechecks authority, category and scored-item protection. No trusted boundary changes and no new native assurance claim. Duplicate labels never replace canonical item ID.

Selection: freezing every input would prevent supported continued work/cancel; value comparison misses ABA and reopen. A per-editor revision increments on user name/category/max, Edit and Cancel, so only the unchanged submitted edit may close/clear. An open flag distinguishes retained editor from explicit Cancel. No write is retried automatically. Cancel discards the current unsent form; it cannot reverse a write already dispatched.
