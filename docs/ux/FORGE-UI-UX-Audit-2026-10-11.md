# LIKHA-SIS — FORGE UI + UX audit and implementation

## Scope and evidence

Audience: teachers completing daily work and school heads managing school records. Outcome: find the correct class, act on current authorized data, preserve unfinished work during navigation, and recover without mistaking an uncertain response for a confirmed save or expiry.

Baseline: `962340650fd531b23fc391bc661ad3f095a98ce7` (M09 integration). Implementation source: `1d1edc5`, isolated branch `recovery/forge-ux-20261010`. The earlier local reconstruction was lost; this audit reports the rebuilt source and current verification, not historical test results.

References applied: the attached DesignMotion philosophy and FORGE UI project module, CTOS golden journey, AGENTS.md, existing class-folio design and tokens. Decision: retain the established visual system, repair its spacing dependencies and shared field treatment, and prioritize trustworthy task states over a new visual theme. Tradeoff: session memory preserves navigation work without introducing an unverified durable/offline draft queue; closing the process still loses unsaved drafts.

Coverage combines a source/state review, project-wide automated tests, and rendered synthetic application-service workflows. There are 36 `*Screen.tsx` surfaces plus shell, hubs, panels, and shared components. The full test suite is broader than the browser journeys. A source review or unit test is not evidence that every native screen has been manually exercised.

## Verification record

Final results are recorded in `VERIFICATION.md`. Browser fixtures use real frontend application services with synthetic in-memory repositories. They do not call native commands or persist school records. Automated axe tags cover WCAG 2 A/AA and 2.1 AA; passing them does not establish complete WCAG conformance.

Browser restriction resolution uses the official Chrome Headless Shell executable. No OS sandbox or host security policy was disabled. Production build isolation separately checks that dev-preview fixtures are absent from distributable output.

No screenshots are included in the delivery, following the latest instruction.

## Recommendations, not verified defects

- P1 release dependency: implement and prove encrypted durable draft recovery on the intended native platforms, with owner scope, explicit discard and recovery after process death. Current session drafts must not be described as autosaved to disk.
- P1 release dependency: exercise Windows installed-app encrypted startup, permissions, scheduling publication, native import/export and backup/restore on this exact source. Android remains unsupported until its Keystore/process-death acceptance passes.
- P2 acceptance: manually test screen-reader announcements, focus order, dialog behavior, 200% text across additional dense forms, physical touch/keyboard and long localized content. The browser suite’s doubled-text case is Today, not every route.
- P2 usability: run a teacher and school-head acceptance session with authorized sample data; measure discovery of Today, class work, planner and recovery actions. No user study was performed.
- P3 performance: measure production startup and large-roster responsiveness before deciding on lazy-loaded feature chunks. The build’s chunk-size advisory is evidence of bundle size, not proof of slow user experience.
