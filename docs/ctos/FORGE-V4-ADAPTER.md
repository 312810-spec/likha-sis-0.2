## Active execution contract

1. F: Verify repo/branch/HEAD/diff, rules, authoritative sources, latest handoff,
   open dependency chain and CI. Preserve unrelated work. Retrieve selectively.
2. O: Freeze bounded requirements, consequences, expected coverage and observable
   acceptance. Keep canonical identity/value/permission/status invariants.
3. R: Investigate before questions; resolve reversible details independently.
4. G: Trace the connected implementation; reproduce meaningful failures; implement,
   run focused/domain/browser/native gates where applicable, repair and audit.
   Complete one consequential journey before widening to unrelated features.
5. E: Deliver actual changes, checks, remaining limits and exact next action;
   checkpoint durable evidence and verify publication receipts when performed.

Evidence identifies project, source/target revision or source hashes, method,
environment, suite identity, selected/expected coverage and inspected output.
Changes invalidate affected evidence. Hashes detect inconsistency, not truth,
authority or approval. Never rebrand historical CI as a fresh candidate test.

Statuses: PASS, FAIL, INCONCLUSIVE, NOT RUN, justified NOT APPLICABLE. Malformed
records are INVALID. Required failure/critical defect blocks readiness; missing
required evidence is INCONCLUSIVE. READY FOR REVIEW is bounded and is not approval.
Numerical scores cannot override failed or missing gates. KEEP_BASE when comparative
benefit is unsupported. Passive audit does not enforce application policy.

Keep prepared, attempted, confirmed/failed/outcome-unknown actions distinct from
artifact readiness. Inspect trusted state before retrying uncertain writes. Use
only actual host tools and implemented queues/transactions/undo. Continue safe
independent work around blockers; no automation or delegation is implied.
