# CTOS checkpoint — M03

**Recorded:** 2026-10-06
**Branch:** ctos/integration
**Parent commit:** 6be509e (M02 checkpoint)
**Status:** PASS

## Outcome

M03's acceptance gate — "no material screen-specific visual island; accessibility
primitives remain intact" — is met. Of the eleven required items, seven already
existed in strong form from the pre-CTOS work; the real gaps were four structural
ones (no type or spacing scale, three duplicate table definitions, six ad-hoc
breakpoints, no shared copy vocabulary), one missing component (a React error
boundary), and the regression fixture itself.

Like M02, a large part of this milestone turned out to be verification rather than
feature work — but unlike M02, the verification found real defects: a type scale
that did not rescale under density modes, three tables that disagreed with each
other, and six one-off breakpoint widths. Each is fixed structurally and each has
a guard that would catch its return.

Accessibility is provably intact, not merely unchanged: the real-browser smoke ran
after every CSS change and reports **zero axe WCAG A/AA findings** across both
appearances × three densities × four widths.

## The four structural gaps

**1. Typography and spacing had no scale.** Sizes were written as literals at the
point of use — ~56 font sizes and ~100 paddings/gaps/margins, each chosen once, by
eye, per screen. Two concrete consequences: the same role could read at different
sizes on two screens, and a teacher switching to the efficient density saw body
text grow while headings stayed fixed, because the density overrides change
`--font-size-base` and nothing else referred to it.

Both scales are now derived from their base:

- nine font steps, `--font-size-2xs` through `--font-size-4xl`, each a
  `calc(var(--font-size-base) * N)`, so density rescales all type together;
- eight spacing steps off `--spacing-unit` (`--space-4` _is_ the unit, the rest are
  calcs);
- a line-height scale and two breakpoint tokens.

The legacy `--font-size-large` / `--font-size-small` names survive as aliases, so
no rule had to be rewritten to keep working. `em` sizing is deliberately left
alone where it is genuinely relative — text inside a labelled control tracking its
label's size is a ratio, not a step.

**2. Three tables, three near-identical definitions.** `.attendance-roster`,
`.section-roster` and `.sf1-comparison-table` each re-declared width, border
collapse, cell padding and border with slightly different values. `.section-roster`
was byte-identical to `.attendance-roster`. They are now one primitive, `.ledger`,
with shared `th`/`td` rules; the SF1 table keeps only the two properties that
genuinely differ. This was a pure refactor, not a restyle — the consolidated values
are the ones the two identical definitions already used.

**3. Six ad-hoc breakpoints.** Media queries used 520, 640, 720, 860, 1080, 1100
and 1200px, with no named tokens and no rule against adding another. These are
consolidated onto three widths — phone (640), tablet (860) and narrow-desktop
(861–1080, where the persistent class index gives up width) — and the two canonical
widths are declared as tokens so JS-side reasoning can share them. A component that
needs a fourth width is now a design decision that has to be made once, in the token
list, rather than per rule.

**4. No shared copy vocabulary.** The shared-state components centralized the markup
and ARIA, but the words were still written inline at every call site, with no
consistent voice. `src/ui/theme/copy.ts` now holds one canonical phrasing each for
loading, offline and error copy, and `RequiresInternetGate` reads from it.

`emptyCopy` was drafted and then **removed**, and the removal is the more honest
result. All 45 `<EmptyState>` call sites name the missing thing and what to do
about it — "No learners enrolled in this section yet." carries real context that a
generic string would discard. Every candidate generic phrasing had no genuine call
site to serve; shipping it would have meant adding a vocabulary entry whose purpose
was to look complete. The module's docstring records this as a conclusion rather
than an omission, so a later reader does not re-add it as an apparent oversight.

## The missing component — no error boundary at all

The single `src/` component gap was a React error boundary: `componentDidCatch` and
`getDerivedStateFromError` appeared nowhere. A render-time throw in any screen
therefore took the whole application down — the shell, the navigation, and every
other tab — because React unmounts the entire tree above the nearest boundary, and
there was none.

`ErrorBoundary` now wraps the tab switch in `App.tsx`, so a failure is scoped to
the screen that failed and the teacher can still navigate away. Four deliberate
choices, recorded in the component's docstring: it renders an alert-toned surface
rather than a bespoke crash page, so a component failure reads like any other
failure; it uses `role="alert"` so the replacement is announced rather than
presented as a silent blank; it surfaces the error message rather than swallowing
it, because a local teacher workstation has no telemetry path and the text is the
only way the teacher can tell a maintainer what broke; and it is scoped to render
failures only, since async service failures already have per-screen error states
that are tested.

App.tsx's diff reads as 288/282 lines but is **7 insertions and 1 deletion** of
substance — the import and the wrapper. The remainder is the mechanical
re-indentation of the tab switch, plus one Prettier re-wrap that the extra
indentation depth forced. Nothing about the screens changed.

## The regression fixture, and what it does not claim

CTOS asks for "visual regression fixtures". This repo ships no image-comparison
dependency (no `pixelmatch`, `sharp` or `pngjs`), no `@playwright/test`, and no
pixel baseline anywhere. Adding one would have meant adding a dependency to assert
the current pixels — which is not the property CTOS names.

`scripts/design-tokens.test.mjs` instead guards the property directly, statically,
against `styles.css`: that a new screen cannot reintroduce a one-off size or an
unknown breakpoint. Ten tests covering the type scale, the spacing scale, the
sanctioned breakpoints, focus rings, motion durations, and the ledger primitive.

This is a **token guard, not a visual regression test**, and the distinction is
stated in the file rather than blurred. What it proves is that the scales stay
derived and the breakpoints stay numbered; it does not prove that any screen looks
right, and the real-browser smoke carries that half of the acceptance criterion.
Both were needed; neither substitutes for the other. A screenshot baseline remains
a defensible future addition if pixel regressions become the risk — it is not a
risk this milestone chose to buy a dependency for.

Every rule in the guard was verified to fail against the pre-M03 stylesheet before
being kept, which is what separates a regression guard from a decoration.

## Items verified as already in place

- **light/dark/system and density modes** — the override blocks in `:root` and the
  `data-teacher-mode` / `data-appearance` attributes were already complete and
  correct. Unchanged; the type-scale fix is what made density honest rather than
  partial.
- **focus** — one real deviation, now fixed: `.concept-folio-panel` used a literal
  `outline-offset: 4px`. Every focus ring now resolves through the shared tokens.
- **motion / reduced motion** — already collapsed centrally under
  `prefers-reduced-motion`. Now also enforced: no component may set its own
  duration outside the tokens.
- **semantic colour tokens** — strong before this milestone, with an existing
  contrast guard at `scripts/palette-contrast.test.mjs`. Unchanged.

## Verification actually run

Full suites in both gates. The browser smoke ran **after** the CSS refactor, which
is the run that matters for a visual milestone. It exercises four widths (1440,
1024, 390, 320) × both appearances × three densities — 24 combinations — and at
each one asserts no horizontal overflow, then runs axe. Below 860px it also scrolls
to the foot of the form and asserts the bottom navigation does not cover the final
control.

Those two assertions are aimed squarely at what this milestone changed. The
breakpoint consolidation moved the phone and tablet boundaries (520/720 → 640, and
861–1080 absorbing 1080/1100/1200), and an off-by-N there shows up as horizontal
overflow — which is what `scrollWidth > innerWidth` catches. The widths were chosen
so that each consolidated band is hit: 390 and 320 sit below the phone breakpoint,
1024 inside the narrow-desktop band, 1440 above it.

## Not claimed

- **No pixel-level visual regression baseline**, by the reasoning above. The
  fixture guards the token properties; the browser smoke guards the rendering.
- **No new accessibility mechanism** — the primitives were already robust; this
  milestone's contribution was proving they survived the refactor, which the
  post-refactor axe run demonstrates.
- **No Rust, no native packaging, no Android evidence.** M03 is a design-system
  milestone; native claims remain where M02 left them.
- The colour-token work predates this milestone and is not claimed as M03 output.
- No M03 case file was added to `docs/ctos/evals/`. The registry's rows are
  behavioural cases — grading, access, schedule, reporting, recovery, Android — and
  the token guard is a property guard, not a behavioural case. Recording it here
  rather than forcing it into a schema it does not fit.
