# Source Registry

Durable third-party sources actually adopted into LIKHA-SIS's development
process or codebase — not a browsing log. Add an entry only when a
decision was actually made. Status values:

- **ADOPT** — in active use.
- **PILOT** — trying it narrowly/experimentally before full adoption.
- **REFERENCE** — studied for principles only, not imported/installed.
- **REJECT** — considered and explicitly declined, with why (prevents
  re-litigating the same question in a future session).

| `Graphify-Labs/graphify` (GitHub) / `graphifyy` (PyPI) | Tree-sitter-based local code-graph generation for AI coding agents (candidate CLI+skill accelerator for architecture exploration) | **REJECT** | Feature set looked plausible on paper (local-only tree-sitter AST for code, TypeScript+Rust support, CLI/skill/MCP/Obsidian options, opt-in strict hook). Rejected at the security-review gate before any install: independently verified via `gh api` — 109,806 stars / 10,675 forks on a repo created 2026-04-03 (4.5 months old), a ~245x gap over the next most-starred same-named project (447 stars), consistent with documented fake-star reputation-laundering abuse, not organic growth. The maintainers were explicitly warned (issue #280, read in full) that the unclaimed single-y PyPI name `graphify` is an active typosquat vector for their real `graphifyy` package and closed it `not_planned`. A cluster of similarly-named satellite repos appeared in the same narrow window. No code from this project was downloaded, cloned, or executed. Full writeup: `.planning/graphify-eval/findings.md`. If revisited later, re-run this exact verification (star history, issue tracker, typosquat status) from scratch — do not assume this rejection stays valid indefinitely without re-checking, but do not re-adopt on stale trust either. |
