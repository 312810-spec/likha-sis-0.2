# Source Registry

Durable third-party sources actually adopted into LIKHA-SIS's development
process or codebase — not a browsing log. Add an entry only when a
decision was actually made. Status values:

- **ADOPT** — in active use.
- **PILOT** — trying it narrowly/experimentally before full adoption.
- **REFERENCE** — studied for principles only, not imported/installed.
- **REJECT** — considered and explicitly declined, with why (prevents
  re-litigating the same question in a future session).

| `proptest-rs/proptest` (v1.11.0) | Property-based testing for Rust, generalizing example-based unit tests into invariants over generated inputs | ADOPT SELECTIVELY (piloted) | Classified ADOPT SELECTIVELY / deferred in the Compounding Engineering pass (`docs/product/COMPOUNDING-ENGINEERING-DECISION.md`); resumed this session as the identified "next best" Phase B pilot target: `repository::user`'s account-lockout invariant (ADR-0019), see `src-tauri/src/repository/user.rs`'s `lockout_properties` test module. Two properties added: lock state exactly matches the `MAX_FAILED_LOGIN_ATTEMPTS` threshold for any attempt count 0-15, and an unknown username never locks regardless of its content or attempt count. Deliberately configured to a low case count (`ProptestConfig::with_cases(8)`, proptest's own default is 256) — every case runs real Argon2id verification (never mocked or test-tuned lighter, per this app's own security posture), so a high case count would slow the suite without proportional coverage gain; ~20-25s combined for both properties, confirmed by direct measurement, not assumed. Added as a `dev-dependency` only (`src-tauri/Cargo.toml`), no production code depends on it. **Selective, not blanket**: not applied to every module — reserved for genuine invariants (a threshold, a boundary, an "for all N" property), not example-shaped logic that's already well covered by targeted unit tests.
